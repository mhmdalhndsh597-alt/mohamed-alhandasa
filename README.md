# محمد الهندسة — مراقبة الشبكة والسيولة

مستودع **mohamed-alhandasa** لمراقبة الشبكة والسيولة وتحليل التحويلات الكبيرة بطريقة منظمة وآمنة.

هذا المشروع مخصص للمراقبة **للقراءة فقط** لعقود وشبكات البلوكشين. لا يوقّع معاملات، ولا يرسلها، ولا يسحب أرباحًا، ولا يتحكم في محفظة باردة. أي تحويل فعلي يجب أن يتم خارج GitHub Actions عبر محفظة باردة أو Safe متعدد التوقيعات وبعد مراجعة بشرية.

## ما يفعله

- يفحص أحدث كتلة عبر RPC ويبحث عن التحويلات الكبيرة فقط.
- يرسل **تنبيه حوت** عندما تتجاوز قيمة التحويل عتبة `WHALE_THRESHOLD_NATIVE`.
- يقيّد التنبيهات بالعناوين الموجودة في `WATCH_ADDRESSES` و`CONTRACT_ADDRESSES` عند تحديدها.
- يرسل Discord Embeds منظمة تشمل المبلغ، الكتلة، المرسل، المستلم، ورابط Blockchain Explorer.
- يسجل الأخطاء في سجل التشغيل، ويرسل تنبيه توقف مختصرًا دون كشف أسرار.
- يفشل مغلقًا عند تعطل RPC أو اختلاف الشبكة، ولا ينفذ أي معاملة.
- يعمل GitHub Actions تلقائيًا كل 5 دقائق، مع تشغيل يدوي متاح.
- يدعم قائمة RPC بديلة عبر `RPC_URLS` وينتقل تلقائيًا عند فشل نقطة النهاية الحالية.
- يقارن حجم الكتلة بمتوسط آخر 24 ساعة ويرسل تنبيهًا عاجلًا عند تجاوز `SPIKE_THRESHOLD_PERCENT`.
- يوفر لوحة Streamlit للعرض الحي عند نشرها على خدمة مستمرة.
- ينشئ تقارير يومية وأسبوعية ويرفعها كـ GitHub Actions Artifacts لمدة 14 يومًا.
- ينشئ مسودات عربية وإنكليزية لفيسبوك وX/تويتر وإنستاجرام للمراجعة قبل النشر.

## متغيرات GitHub

ضع القيم العامة التالية في **Actions Variables**:

- `CHAIN_ID` — رقم الشبكة، مثل `1`.
- `WATCH_ADDRESSES` — عناوين مفصولة بفواصل للمراقبة، ويمكن تركها فارغة لمراقبة كل التحويلات الكبيرة.
- `CONTRACT_ADDRESSES` — عناوين العقود ذات الصلة، مفصولة بفواصل.
- `WHALE_THRESHOLD_NATIVE` — الحد الأدنى بالعملة الأصلية، مثل `100`.
- `SPIKE_THRESHOLD_PERCENT` — نسبة التغير عن متوسط 24 ساعة، مثل `50`.
- `EXPLORER_TX_URL` — قالب رابط المعاملة، مثل `https://etherscan.io/tx/{tx_hash}`.

ضع القيم التشغيلية الحساسة التالية في **Actions Secrets**:

- `RPC_URL`
- `RPC_URLS` — اختياري؛ روابط RPC مفصولة بفواصل، بالترتيب الأساسي ثم البدائل.
- `DISCORD_WEBHOOK`
- `SOCIAL_WEBHOOKS` — اختياري؛ Webhooks إضافية مفصولة بفواصل للنشر الإخباري فقط.
- `FACEBOOK_PAGE_ACCESS_TOKEN` — محجوز لربط مستقبلي، ولا يستخدمه النظام الحالي.
- `TELEGRAM_BOT_TOKEN` — محجوز لربط مستقبلي، ولا يستخدمه النظام الحالي.

لا تضف أبدًا مفاتيح خاصة، seed phrases، رموز وصول لمحافظ، أو مفاتيح توقيع إلى هذا المستودع أو GitHub Actions أو Discord. لا توجد في المشروع دالة توقيع أو إرسال معاملات.

## التشغيل المحلي

```bash
export RPC_URL="https://your-read-only-rpc.example"
export CHAIN_ID="1"
export WHALE_THRESHOLD_NATIVE="100"
export EXPLORER_TX_URL="https://etherscan.io/tx/{tx_hash}"
python monitor.py
```

## لوحة التحكم

ثبّت متطلبات اللوحة ثم شغّلها على جهاز أو خدمة مستمرة:

```bash
pip install -r requirements-dashboard.txt
streamlit run dashboard.py
```

لوحة التحكم للعرض فقط، وتقرأ نفس متغيرات البيئة. GitHub Actions لا يستضيف عملية Streamlit دائمة؛ لذلك يجب نشر اللوحة على خدمة تشغيل مستمرة إذا كان المطلوب تحديثًا حيًا.

## التقارير وحالة 24 ساعة

يُحفظ سجل الحالة في `data/volume_history.jsonl` أثناء التشغيل، وتُنشأ التقارير في `reports/`. لأن GitHub Actions يستخدم خوادم مؤقتة، يرفع Workflow هذه الملفات كـ Artifacts بدل تعديل المستودع تلقائيًا أو منح Workflow صلاحية كتابة على الكود.

## أتمتة المحتوى والربط المستقبلي

يحتوي `social_content.py` على مولد حتمي للمسودات وقوالب طلبات Facebook Graph API وTelegram Bot API. القوالب لا تنفذ طلبات ولا تحتوي على Tokens؛ أي نشر مستقبلي يجب أن يمر بمراجعة وصلاحيات Secrets منفصلة. الهاشتاجات الحالية قائمة تحريرية مناسبة للمجال وليست ادعاءً بترتيب تفاعل لحظي من منصات التواصل.

## التسجيل

تظهر السجلات في مخرجات GitHub Actions. ولحفظها محليًا يمكن ضبط `LOG_FILE` على مسار ملف محلي؛ لا تستخدمه لتخزين الأسرار.

## حدود النطاق

أوامر Discord للتحويل أو التوقيع أو تشغيل/إيقاف معاملات مالية غير مدعومة. Webhooks الإضافية تنشر إشعارات فقط، مع `allowed_mentions` معطلة لتقليل مخاطر الإزعاج أو الإشارات غير المقصودة. جدولة GitHub Actions قد تتأخر قليلًا بسبب ازدحام GitHub، لكنها مضبوطة على فاصل 5 دقائق.
